# NavPro — SetCreator

Version 1.0.27 targets separate Navisworks Manage 2024, 2025 and 2026 plug-in binaries from their matching API assemblies. The HTML dashboard uses a dark slate analytics layout with a NavPro logo and wordmark at top left, weekly status trend and stacked charts, a current-week status donut, discipline-pair heatmap, week-over-week comparison, KPI cards and the full filterable Clash Register. Weekly snapshots use the latest loaded report per project per week. Resolution Rate is Resolved / Total. The Clash Review panel includes XML/CSV **Import Clash Status**, **Refresh Models** for reloading changed referenced files, and **Colorizer** for random or Excel-mapped permanent appearance colors on loaded models or saved sets. Typography uses locally installed Jacobs Chronos with Arial/system fallback. No proprietary font files are distributed. See `Docs/Jacobs-Branding.md` for training links and verification limits. Builds/packages are not installation or native Manage UI verification.

Autodesk Navisworks Manage **2024, 2025 and 2026**, x64, .NET Framework **4.8** plug-in. Each major release uses a separately compiled binary and matching API references: Manage 2024/API 21 in `Contents/v21`, Manage 2025/API 22 in `Contents/v22`, and Manage 2026/API 23 in `Contents/v23`. The visible tool name is **SetCreator**. The original `SearchSetCreater` command ID is retained for compatibility. Mytools is not referenced, edited, deployed or required.

## Build and share

Prerequisites: Visual Studio 2022 with .NET desktop development, a .NET SDK supported by that Visual Studio installation, and the .NET Framework 4.8 targeting pack; or a compatible `dotnet` SDK/MSBuild for command-line builds. The 2024 API references come from Manage 2024; the 2025 and 2026 API and Clash references are supplied under `Manage 2025 DLLs` and `Manage 2026 DLLs` by default or can be passed explicitly. Use the matching releases' `Autodesk.Navisworks.Api.dll` and `Autodesk.Navisworks.Clash.dll`. This machine's command-line verification uses SDK 10.0.400; the Visual Studio 2022 IDE itself was not verified. No third-party runtime dependencies. Do not redistribute Autodesk DLLs.

Open `NavPro.sln`, select Release / x64 for Manage 2024, Release2025 / x64 for Manage 2025, or Release2026 / x64 for Manage 2026, then Build Solution. Release2025 and Release2026 default to the supplied `Manage 2025 DLLs` and `Manage 2026 DLLs` API folders; override the corresponding API directory parameter if your matching references are elsewhere. Release uses the default `C:\Program Files\Autodesk\Navisworks Manage 2024` path. SDK-style project settings specify x64 even though the solution maps the internal project configuration to Any CPU.

From PowerShell in this folder:

```powershell
.\Tools\Build-Package.ps1
# Non-default 2024 installation and 2025 API directory:
.\Tools\Build-Package.ps1 -NavisworksInstallDir 'D:\Autodesk\Navisworks Manage 2024'
# .\Tools\Build-Package.ps1 -Navisworks2025ApiDir 'D:\Autodesk\Navisworks Manage 2025\api'
# .\Tools\Build-Package.ps1 -SkipTests -CreateZip
```

This generates deterministic code-native 16px/32px icons, builds and metadata-checks separate 2024, 2025 and 2026 binaries against their matching core and Clash APIs, optionally runs policy/adapter tests, then validates bundle paths, runtime targets, asset sizes and DLL SHA256. ZIP creation is opt-in with `-CreateZip`; use `-SkipTests` to skip the test executable. Autodesk assemblies are reference-only and are not copied into the bundle. Outputs:

- `dist/NavPro.bundle` — ready-to-copy deployment folder.
- `dist/NavPro-1.0.21-Navisworks2024-2025-2026.zip` — optional shareable plugin package containing all three release binaries (created only when requested with `-CreateZip`; no source or Autodesk binaries).

The source manifest is `Deployment/NavPro.bundle/PackageContents.xml`. Build packaging populates its Contents directory in `dist`, not in the source template. Each version-specific `CommandHandlerPlugin` binary has its ribbon layout and relative icons beside the assembly and under the matching `Contents/v21/en-US`, `Contents/v22/en-US` or `Contents/v23/en-US` folder to cover Navisworks UI-language layout resolution.

## Install and load

Close Navisworks first. For this Windows user run:

```powershell
.\Tools\Install-NavPro.ps1
```

It installs only NavPro to `%APPDATA%\Autodesk\ApplicationPlugins\NavPro.bundle`, backs up an older NavPro outside discovery to `%LOCALAPPDATA%\NavPro\Backups`, and verifies copied file hashes. It refuses to replace files while `Roamer.exe` is running. It does not modify Mytools or other plugins. Running a build/package does **not** install it automatically.

For other users: unzip the shareable ZIP under `%APPDATA%\Autodesk\ApplicationPlugins`, retaining `NavPro.bundle/PackageContents.xml` and `NavPro.bundle/Contents/...`. If Windows marks downloaded files as blocked, use the ZIP Properties > Unblock before extracting, following company IT policy. Remove any separately installed duplicate NavPro copy before testing; do not load the same DLL through both bundle and Plugins paths.

Start **Navisworks Manage 2024, 2025 or 2026**, not Freedom. Use the custom **NavPro** ribbon tab. The **Search Sets** panel contains **SetCreator**; the **Clash Matrix** panel contains **Clash Matrix**; **Clash Review** contains **Renamer**, **Tolerance Updater**, **Status Updater**, **Import Clash Status**, **Refresh Models**, and **Colorizer**; **Export** contains **Clash Dashboard**; and **Help** contains **Contact Info**. Colorizer can apply random or workbook colors to loaded models or saved Selection / Search Sets. Leave targets unchecked to include all in the chosen mode, or check specific targets. Its Excel workbook uses target type/name/key and editable `Color Hex` or RGB values; imported names must match Navisworks, and duplicate names need the exported key. Colors are permanent appearance overrides; save the NWF/NWD to retain them. Refresh Models calls Navisworks `Document.UpdateFiles()` for changed files at existing model paths. It does not append new models or remap moved files; after refresh, inspect the model and rerun clash tests as needed. Contact Info displays the support email copied from the MyTools plugin and provides a user-initiated copy action. The `CommandHandlerPlugin` is described by stable plug-in identity, ribbon-layout, tab, and command attributes; `SearchSetCreaterRibbon.xaml` defines the panels. If missing, inspect **Home > App Manager**, confirm the manifest targets the correct NAVMAN series and the matching DLL plus XAML exist in that version folder, and restart. **NETLOAD is an AutoCAD command, not the Navisworks loading mechanism.**

In Clash Matrix, each A/B selector has Standard, Compact, Properties and Sets views. **Standard** lists one loaded model file per row and uses the model root as the clash selection; **Compact** lists model-tree child nodes. Properties lists saved Search Sets, and Sets lists saved Selection and Search Sets. The A/B selection panels have extra height to show more choices. Choose A/B geometry primitives (surfaces, lines, points) alongside test type and tolerance. The tolerance-unit dropdown includes the Navisworks distance units; entered values are converted to document units before the test definition is created. **Self-Intersect** and **Exclude Self-Self** are mutually exclusive modes applied consistently to both selections: Exclude Self-Self leaves both native `ClashSelection.SelfIntersect` values off; Self-Intersect turns both on. **Composite Object Clashing** maps to `ClashTest.MergeComposites`. Prefix and Separator controls regenerate proposed clash names; individual names remain editable in the preview. Preview shows the composite setting and summarizes existing test profiles and read-only result statuses; it never runs a test. New ClashTest definitions are added to the Clash Detective Tests root using the typed `DocumentClashTests.TestsAddCopy(ClashTest)` overload; the generic group overload rejects ClashTest items under folders. There are no Excel import/export actions for Clash Matrix definitions. **Clash Dashboard** exports a self-contained HTML report of saved test definitions and results with status totals, discipline-pair summaries, filters, CSV, print-to-PDF, optional viewpoint images and optional tabular HTML/XML companions.

In **Status Updater**, select one or more saved Clash Detective tests, choose any standard Navisworks result status (New, Active, Reviewed, Approved or Resolved), preview the current status breakdown and proposed changes, then confirm. Results already at the target status are skipped. The Updated by value is required and recorded only when setting Approved. Leaf results are updated without counting grouped containers twice; tests are not rerun. Status changes affect the document's clash review history.

In **Import Clash Status**, choose a NavPro Dashboard XML/CSV export or standard Navisworks Clash Detective XML export, then load it and select which report statuses to include. **Preview changes** matches by clash test and clash result name, and also by both item names when the export includes them; CSV model names are used when present. Only unique matches with a changed status are eligible. Conflicting, ambiguous, missing or incomplete rows remain unchanged. Review the preview, enter the updater name used for newly Approved results, and click **Import** to confirm the batch. Save the model in Navisworks to retain the imported native status changes. This tool does not import assignment edits or rerun clash tests.

In the **Export** ribbon panel, choose **Clash Dashboard** to export current saved Clash Detective tests and results to a portable HTML dashboard. Setup includes project name, output units, the five native result statuses, all kept versus selected-status scope, and optional per-clash images. Dashboard content includes a historical **Status of Clashes and Date** clustered column chart above the KPI cards, a **Loaded Reports** list showing project name and report creation date with **All** and **None** selection controls that apply only to loaded-report selection, status/priority/discipline filters, Select All/Select None shortcuts for Discipline A and B, AND/OR logic, discipline-pair summaries, a paged clash register with individual and bulk assignment, CSV export, loading other NavPro dashboards and browser print-to-PDF. Left-panel filters cascade to values with matching records and update KPIs, status flow, discipline summaries, register and historical chart together; **Reset Filters** clears slicers, search and visual selections. Choose **Select Reports Folder** to load saved NavPro HTML dashboards from a directory; in supported browsers the selected folder is rescanned every 15 seconds while the dashboard is open, and its access handle is remembered when the browser permits. Folder access requires user selection and browser permission. If live directory access is unsupported, choose the folder through the fallback picker or use Add Files again after new reports are saved. Use the report snapshot slider or **Play history** to move dependent visuals through the timeline together; selecting a dated column group does the same. When detailed clash rows are unavailable in an imported compatible report, per-test status summaries still drive aggregate visuals; an aggregate-only report cannot be split accurately by discipline or priority, and its detail register remains empty. Optional tabular HTML and NavPro XML companions can be generated. Export reflects saved results and does not run or refresh tests. Priority and complete Discipline A/B values are parsed from each Clash Test name using `Priority_DisciplineA_VS_DisciplineB` (for example, `H_CI-Irrigation_VS_CS-Storm` gives `H`, `CI-Irrigation`, and `CS-Storm`). Invalid names are flagged in the Clash Tests table and use Unclassified in discipline filters. The `VS` token is only the delimiter and is excluded from extracted values and dropdowns. Manual priority edits and assignment overrides are local browser review notes and do not modify the NWF/NWD. The API does not expose viewpoint titles. Optional image rendering is synchronous and may take time.

The HTML dashboard uses a dark slate surface system with the NavPro magenta accent and semantic clash-status colors. To reduce refresh time on large reports, it caches normalized rows, coalesces filter changes into one animation-frame refresh, and pages the Clash Register at 100 detail rows while calculating metrics over the complete filtered set. Add `?navproDebug=1` to the dashboard URL to log refresh timing and filter context in the browser console. Missing controls, incompatible report files and render failures also produce diagnostics.

Fallback diagnostic (do not use alongside an installed bundle): launch Manage 2024 with `Roamer.exe -AddPluginAssembly "C:\full\path\NavPro.dll"`; keep its Assets folder beside the DLL. This can isolate bundle discovery issues.

## Use

1. Open or append your model; click NavPro - SetCreator.
2. Choose between two setups:
   - **Option A — Property setup** keeps project-specific control. Scan all model properties, select Category and Property, choose **All values** or one exact value, preview matches, and optionally rename each result before creating. For File Name/model-number properties with path-valued display strings, preview labels and default set names use only the filename (including its extension), and the dynamic search uses a filename-suffix wildcard. This keeps saved queries independent of each user's folder path while still matching full-path property values. Other properties and non-path values retain their stored value. Use this option when a project's model-number field differs, when another property is required, or when the detected model-number property is ambiguous.
   - **Option B — File Name setup** supports multiple loaded models (all checked by default; uncheck any to exclude it). It reads exactly **Category: Item / Property: File Name** from the checked model hierarchies, previews each distinct nonblank typed value and match count, then creates one dynamic search set per filename. Folder paths are excluded using a filename-suffix wildcard, and the default set name is the filename; duplicate filenames across checked models produce one set. It uses the SDK's `PropertyCategoryNames.Item` and `DataPropertyNames.ItemFileName` constants. Search queries are document-wide, so equal File Name values in an unchecked loaded model can also match. Use **Rename / Edit** on a preview row to change the set name before creation. Invalid or duplicate names are flagged and can be corrected before creation.
3. In either option, a case-insensitive existing saved-item name anywhere in the Sets tree is **skipped**. No existing item is edited/deleted or replaced. No model or folder path is used in the default set name. Creation adds new sets to a `NavPro - SetCreator` folder (numbered folder if needed); an empty folder is not added.
4. Option A's table shows model number, resulting set name, validation/skip state, and a **Rename / Edit** action. Use the horizontal scrollbar to move left and right across the columns; the vertical scrollbar navigates long previews. Its conservative naming policy rejects blank names, leading/trailing whitespace, control characters, `\ / : * ? " < > |`, names longer than 240 characters and case-insensitive duplicate batch names. These are NavPro safety rules, not a claim about all native naming restrictions. No silent normalization occurs.
5. Review completion/skipped counts. **Save your NWF/NWD** using Navisworks to persist the sets. NavPro does not save, overwrite or export model files automatically.

### Clash Matrix — Matrix Designer

1. Open **NavPro > Clash Matrix > Clash Matrix** with a loaded Manage document. Refresh to read loaded model names, all saved Selection/Search Sets, current item counts during preview, and existing Clash Detective test profiles.
2. Check one or more discipline/system sets under **Selection A** and **Selection B**. Choose Hard, Hard (Conservative), Clearance, or Duplicate and enter a tolerance. The units dropdown converts the displayed value when changed to preserve the same distance; the document's units remain unchanged, and preview values are shown in document units. NavPro does not presume a universal project tolerance.
3. Click **Preview matrix**. Review every proposed A/B pair, name, type, tolerance, and validation. Empty sets, self-pairs, duplicate pairs/names, existing clash-test names, and mixed existing profiles are surfaced for review.
4. **Create previewed tests** adds only rows marked Ready as Clash Detective test definitions to the Tests root. Existing tests are preserved. After successful creation, **Run Clashes** runs only the tests created by that action in this dialog; it does not run unrelated existing tests. Navisworks runs each native test synchronously, so the dialog can pause during an individual run and cannot safely interrupt that call. Review results in Clash Detective, then save the NWF/NWD.

Matrix Designer creates test definitions only; it does not run tests or generate results. The separate **Export > Clash Dashboard** tool summarizes saved tests/results and supports browser-local review notes. Browser-side priority and assignment edits do not write back to Clash Detective. Dashboard priority, discipline, status, loaded-report and clash-test filters coordinate KPI cards, flow, discipline summary, register and historical column chart from the filtered result data. The clash-test selector beside **Overall Clash Report / Discipline** supports multi-selection, **Select All**, and **Select None**; its options come from the currently selected reports and snapshot. Priority options are parsed from clash-test name prefixes. The Clash Tests section is omitted. Bulk Assign applies a member name to selected clashes or the current page/filtered set; these assignment notes are stored in browser local storage and do not modify the NWF/NWD. **Clash Review > Renamer** loads saved tests, supports find-next/previous, inline multi-test edits and prefixing checked rows, then validates and confirms the rename before updating names while preserving test definitions and results.

### Keep the dialog available while working

SetCreator opens as a modeless window, so you can return to Navisworks and continue working while the dialog remains open. Turn on **Pin window** to keep it above Navisworks; turn it off to use normal window stacking. Model/document changes invalidate the current scan or preview, so rescan after changing the loaded models. A synchronous native search can still temporarily occupy Navisworks while that specific search call runs.

## Search semantics and limits

- Search criteria use `SearchCondition.HasPropertyByName(internalCategory, internalProperty).EqualValue(originalVariantData)` and `Search.Selection.SelectAll()`. `SelectionSet(Search)` saves a dynamic query, not a static list of model item IDs. `PruneBelowMatch=false` includes every directly matching hierarchy item. Counts may include file roots, groups and geometry; they are not unique geometric-object counts. Ancestors' values are not copied onto descendants. Rerunning the saved search includes newly matching items in the current document.
- Text, identifier strings, integers, all double scalar types, dates, booleans and named constants are supported. Typed values do not collapse into display strings; named constants group by internal constant name. Points/other unsupported types are counted and excluded. SDK equality semantics determine actual matches; preview uses the same factory as creation.
- Every SDK call stays on the original Navisworks UI thread. The modeless, parented WinForms dialog allows the host to remain interactive between operations; document/model change events invalidate the session. Scans yield between approximately 35ms batches; set preparation yields every 20 entries. No Task.Run, DoEvents, background native API access or unsafe reentrancy inside commit.
- Discovery/collection totals are unknown until traversal completes: animated indeterminate ring + processed count, no fictitious percentage. Native count validation and preparation have known value totals: percentage and **approximate stage-local ETA**, after at least two values and one second. Elapsed time covers this dialog session. ETA is workload-based, not a guaranteed whole-operation finish time.
- The upper-right progress card uses a rounded circular indicator: the ring centers the known percentage, while unknown-total work shows an animated indeterminate arc. Stage and approximate ETA remain adjacent to it.
- A single `Search.FindAll(document,true)` is synchronous and may block custom status updates; native progress/cancellation is requested. The tool checks Cancel between batches and queries, and handles `CanceledOperationException`. It cannot safely interrupt a native call that is not yielding. Final AddCopy/Commit is deliberately non-cancellable. Closing during a task requests cancellation rather than disposing active controls.
- Model collection/property events and active-document changes invalidate the session; close/reopen and rescan. A full refresh/import is required if the selected property is not exposed by the source model.
- All new sets are prepared in a detached folder, cancellation/names rechecked, then one supported `Document.SelectionSets.AddCopy` occurs inside `Document.BeginTransaction`. Installed 2024 documentation says transactions batch edits and **does not guarantee rollback**. Unexpected commit errors may leave the newly added folder: inspect Sets before retrying. Existing saved items are never deliberately altered.
- This assembly is compiled only for the installed **21.0 API / Navisworks 2024**. Rebuild and independently verify against the SDK for another major release. No Civil 3D or COM API assumptions are used.

## Code layout

- Open `NavPro.code-workspace` for the NavPro-only VS Code workspace. Build/test/package tasks are included; see `Docs/DEVELOPMENT.md` for the folder map and development workflow.
- `Classes`: shared host-independent classes and product/tool identity constants.
- `Docs`: project organization and developer guidance.
- `Frontend/Plugins`: SDK plug-in registration, custom ribbon XAML and document validation.
- `Frontend/Dialogs`: selection, naming preview, progress and error UI.
- `Backend/Core`: pure naming, criteria descriptors and ETA policies.
- `Backend/Models`: property options, inspection results and typed values.
- `Backend/Services`: UI-thread model inspection, native search factory, safe new-set creation.
- `Tests`: dependency-free executable tests. Tests compile the real criteria factory against **test doubles**, not the native SDK. These test our generated calls/typing; they do not establish native search behavior.
- `Assets`, `Tools`, `Deployment`: deterministic icons, verification/build/install scripts, bundle template.

## Manual Navisworks verification checklist (required)

No in-host verification is implied by a successful build or metadata check.

1. Install as above, restart Manage 2024, verify the NavPro ribbon tab, Search Sets panel, SetCreator button, 16/32px icons, dialog title and readable controls at your Windows DPI.
2. With no model, confirm the actionable warning. Load a small model with known model-number property values `001`, `002`, missing, blank; verify Option A's chosen internal property and distinct preview/missing/blank counts against **Find Items**.
3. Create with model-number-only names, then use **Rename / Edit** on one row. In Sets, confirm the custom set name, dynamic search-set icons and use Find Items to inspect the exact property/value condition. Double-click each saved set and compare actual selected counts with preview. Include hierarchy matches in the comparison.
4. Save as a test NWF, close/reopen, rerun each search. Append/update a model with another item having `001`; rerun the saved search and verify it includes that match. No stale explicit item selection should be stored.
5. Repeat same generation: verify all names skip, no empty folder and no existing set changed. Test pre-existing same-name sets in nested folders; they must be skipped. Test case-duplicate values, reserved characters, same displayed value with different native types, and an unsupported property type.
6. Scan a larger model: verify marquee/count, known-total percentages, approximate stage ETA, normal window repaint and cancellation at safe points. Test native progress cancellation during FindAll. No saved-set mutation should occur before commit; commit itself is not cancellable.
7. Test a property with no supported nonblank values; confirm an actionable message. Close the dialog during scan/preview/preparation and verify cancellation leaves it stable. Test model refresh between sessions and rescan.
8. Test Option B with at least two loaded models. Confirm all are checked by default; uncheck one and verify the preview excludes its values, then change the checked set and confirm the old preview is invalidated. Verify full paths display/default to the filename and the condition is `Item / File Name = filename` without a user-specific folder path; duplicate filenames across selected models produce one row/set. Exercise Rename / Edit with valid, invalid, duplicate and existing names before creation. Inspect document-wide query matches, including equal File Name values in unselected models. Test missing/blank/unsupported values.
9. Preserve an original NWF copy and compare the existing Sets tree after success/cancel/errors. Unexpected commit failure recovery: inspect and optionally remove **only the new NavPro folder manually**, never assume rollback.

### Tolerance Updater

The **Clash Review** ribbon order is **Renamer**, **Tolerance Updater**, then **Status Updater**. Open **Tolerance Updater** and check any combination of saved tests, or use **Select all / Select none**. The initial tolerance comes from the first listed test; verify it against project requirements. Enter a non-negative distance and choose its units. Keep each test's existing type, or apply **Hard**, **Hard (Conservative)**, **Clearance** or **Duplicates** to every checked test. There is no universal project tolerance preset.

The **Composite Object Clashing** selector is placed below the settings and guidance row. Choose **Keep current** to preserve each selected test's existing value, or explicitly set **Enabled** or **Disabled** for the selected tests. The preview shows current and proposed composite settings alongside the type and tolerance.

Click **Preview changes** to compare current and proposed settings in document units. **Apply preview** confirms the batch and skips unchanged tests. Changing inputs or selection clears the preview. If selected tests, their names/settings, or document units changed in Navisworks, refresh and preview again. Test GUIDs are re-resolved immediately before edits. The updater copies each complete current test and uses `TestsEditTestFromCopy` to edit its settings; it does not create replacement tests, edit result statuses, or save the document. Existing simulation links and steps, rules, and selections are retained; the composite setting is preserved with **Keep current** or changed only when explicitly requested. Use **Re-Run Clashes** beside **Preview changes** to rerun only checked tests; apply a changed preview first. Navisworks runs these synchronously and cannot be safely interrupted from the tool. Review results and save the document when ready.
