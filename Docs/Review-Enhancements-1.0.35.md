# Review workflow enhancements — 1.0.35

This is a development and verification record. Build/test-double results do not establish native Navisworks acceptance.

## Implemented workflows

- **Refresh Models:** file availability, size and UTC modification observations; comparisons with the last NavPro inspection; native refresh summary; test last-run information and a potentially-outdated warning after a native refresh. Published NWD source paths are identified as possible embedded provenance, not automatically treated as lost geometry. Filesystem access failures cannot distinguish missing files from permissions/offline storage. No loaded-file timestamp is invented.
- **Description Assistant:** named, editable local project templates. Fields: `{SystemA}`, `{SystemB}`, `{Level}`, `{Chainage}`, `{ItemA}`, `{ItemB}`, `{Test}`, `{Clash}`. Missing/ambiguous values become visible markers; Apply rejects remaining markers. Metadata does not infer chainage from coordinates. Manually edited drafts are skipped by generation. Style changes, cancellation and generation failures retain drafts. A changed native snapshot still requires reload. Built-in drafting remains offline.
- **Colorizer:** editable colour legend before random/import/palette application; named local discipline palettes; preview and explicit Apply. Double-click a legend row to choose its colour. Palettes match current target names/keys. Preview displays assignments; it does not temporarily recolour the model. Native API 21 `ModelGeometry.PermanentColor` does not distinguish original versus explicitly overridden colour; `ResetPermanentMaterials` also resets transparency. An exact NavPro-only restoration command is therefore **not offered**.
- **Smart Clash Grouper:** deterministic 3D connected-distance clusters, level/zone grouping and per-member explanations. Each cluster member connects to another member within the radius; cluster diameter can exceed that radius. Radius is in document units. Existing groups, ineligible resolved clashes, missing/conflicting metadata and singletons remain excluded. A 10,000-eligible-results-per-test limit bounds the pairwise calculation.
- **SetCreator:** saved property/naming presets (`{value}`, `{n}`), explicit selected-row model selection, empty-query feedback and direct membership overlap checks against up to 50 existing saved sets. The preview runs native searches only on explicit request. It does not establish ancestor/descendant geometric coverage or scan every existing set in very large documents. Existing sets are preserved.
- **Renamer:** existing 1.0.33 naming presets, automatic numbering and before/after changed-span highlighting are retained. Pattern staging and validation precede native Apply.
- **Chainage Locator:** schematic alignment plan, explicit XY scale/CCW rotation/translation, unit conversion, `1+250` station labels and validated increasing-progression station equations. Translations use alignment units, after unit conversion, scale and rotation. Z is only unit-converted. Check known survey/control points before accepting a transform. Equations require finite, ordered internal/back/ahead stations within the alignment and consistent incoming stations. CSV remains continuous internal station geometry. No CRS or live Civil 3D connection is implied.
- **Utility Separation:** approved CSV and first-worksheet XLSX import; literal values, explicit source/revision and `Approved=Yes` required. Header: `Rule,SetA,SetB,Gap,Units,Source,Revision,Approved,CheckType`. Use full set paths or GUIDs when names are ambiguous; Units uses Navisworks names such as `Meters`. `CheckType=3D` uses the native surface-gap engine. Imported rules are reviewed/previewed before test creation; creation and execution remain separate.
- **Coordination Change Log:** local history keyed by normalized saved document path; explicit revision snapshots and comparison of the latest two labels by result GUID. Captures names, descriptions, statuses, groups and coordinates. Partial native colour/spatial run failures and stopped review operations are recorded as incomplete/unverified. It is a record of NavPro operations and explicit snapshots, not a complete native audit or Undo. Unsaved documents remain in memory. Save As starts a distinct path history. Preset/history files have an 8 MB JSON bound and persistence errors are surfaced.
- **Clash Dashboard:** image generation is requested for every included leaf result, including results without a manually saved viewpoint. Each native failure/null image is identified in its row; export reports generated/unavailable image counts. Image capture remains synchronous on the host thread. All-result native image success still requires testing on the supplied federation.

## Geometry enhancements still requiring development and independent verification

Spirals, decreasing station progression, horizontal-only/vertical-only utility gaps and crossing-specific geometry are not implemented/certified by this release. Unsupported inputs are rejected rather than silently interpreted as supported checks. The supplied folder contained an NWD only, with no alignment, approved separation rule table or geometry ground-truth cases. These inputs are necessary for project acceptance, and additional geometry implementation/validation remains required.

## API evidence

Native calls compile against installed Manage 2024 API 21, with matching builds for API 22/23. The API 21 XML documents permanent colour and material-reset behavior. Existing public `TestsImageForResult` is now invoked without the previous saved-viewpoint filter. Autodesk's [Results tab documentation](https://help.autodesk.com/cloudhelp/2020/ENU/Navisworks/files/GUID-FCC9E5E1-2717-48D2-8DBE-2055CF2DC61E.htm) describes potentially outdated results after test/model changes. [FHWA's LandXML schema analysis](https://www.fhwa.dot.gov/bridge/pubs/hif16011/hif16011c.pdf) identifies station-equation internal/ahead/back/increment fields; this is not native-host verification.
